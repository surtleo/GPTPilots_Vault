
작성자 이찬울

1. 프로젝트는 다양한 AI 모델을 활용하는데 학습 및 평가 비용이 많이 발생할 수 있으므로 Google Cloud Platform의 실행에 초점이 맞춰져 있다. 하지만 가벼운 테스트 환경이 필요하다면 로컬에서도 프로젝트를 실행할 수 있다. vscode와 git bash를 활용하여 프로젝트를 실행하여 본다.

2. 프로젝트 실행 순서

	ㄱ. github에서 로컬에 clone이나 pull을 하여 프로젝트를 로드한다. 프로젝트로 폴더를 이동한 후, git bash를 실행한다.
	
	ㄴ. uv --version을 통해 uv 설치되어 있는지, 최신버전인지 확인한다.
	
	ㄷ. uv 가상환경을 세팅하기 전에, uv python install [프로젝트에 필요한 파이썬 버전] 을 입력하여 프로젝트에 맞는 파이썬 버전을 설치한다. 이 파이썬 버전은 uv run, uv venv와 같은 uv 명령어를 통해 파이썬 프로그램을 실행하는 경우에 로컬에 설치된 파이썬 버전과 다른 버전이다.
	
	ㄹ. uv venv 를 입력하여 uv 가상환경을 켜는데 초기화를 진행한다. 사용자에게 초기화를 하여야하는지 물어보면 'y'키를 누른다.
	
	ㅁ. .venv를 입력하고, 가상환경을 켜는데 필요한 입력을 확인한다.
	
	ㅂ. 해당 키를 입력한다. (ex : $ source .venv/Scripts/activate)
	
	ㅅ. 가상환경이 켜지면 uv sync로 .toml 파일에 있는 라이브러리들을 버전에 맞게 설치한다. 가상환경에 설치하는 것이지, 실제 로컬 드라이브에 설치하는 것이 아니다.
	
	ㅁ. (가상환경 이름) 이 표시되어있는지 확인하고, 자유롭게 파이썬 명령어를 이용한다.

3. 이렇게 실행하는 이유는, Powershell 환경이나 CMD 터미널 환경은 리눅스의 Bash 쉘 환경과 다르기 때문이다. 로컬의 GPU를 보완하기 위해 GCP 환경을 사용하는데, GCP의 os는 리눅스 기반, 로컬은 윈도우나 맥 기반이기 때문에 CLI 명령어가 맞지 않는 경우가 많다. 이 방법의 장점은 git 프로그램이 기본적으로 bash 쉘을 사용하기 때문에, 깃 버전 관리를 하면서 프로그램을 uv 가상환경에서 실행시켜볼 수 있다는 점이다.

4. Git Bash의 문제 : 출력창이 기본적으로 **MinTTY**(Minimal Terminal Emulator)를 사용하여 파이썬 프로젝트를 실행하면 결과화면이 가독성이 떨어질 수 있다는 단점이 있다. D2Coding(폰트) 다운로드하여 줄간격을 조절해가며 사용하거나, 최신 윈도우 터미널 환경 Windows Terminal을 Microsoft Store에서 다운로드하여 Git Bash의 가독성이 떨어지는 화면을 조정하여 사용한다.
