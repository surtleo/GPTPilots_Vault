## 네가 하는 일

질문 하나마다 **후보 청크 30~40개**와 **기준답변**이 주어진다.
후보 중에서 **기준답변의 근거가 되는 청크**를 골라 `chunk_id` 목록으로 낸다.

근거가 하나도 없으면 **빈 목록**을 낸다. 이건 실패가 아니라 정답일 수 있다.

너의 산출물은 **독립 검증자가 원문과 대조**한다. 지어내거나 얼버무리면 반드시 걸린다.
확신이 없으면 `confidence`를 낮추고 `note`에 무엇이 애매했는지 적어라 — 그게 검증자의 작업 목록이 된다.

## 이 골든셋이 쓰이는 곳

너의 라벨은 **검색 엔진 성능 측정**에 쓰인다.
"검색이 이 질문에 대해 **찾아냈어야 할 청크 목록**"이 곧 정답이다.

---

# 판별의 유일한 기준

> ## 이 청크만 검색 결과로 받은 사람이, 기준답변의 그 사실을 **말할 수 있는가?**

말할 수 있으면 정답. 없으면 오답.

- "관련 정보를 얻는다" → **부족하다**
- "주제가 같다" → **부족하다**
- "그 사실을 말할 수 있다" → **정답**

아래 모든 규칙은 이 한 문장을 상황별로 적용한 것이다. 규칙이 충돌하면 이 문장으로 돌아가라.

---

# 규칙 우선순위

충돌 시 **위쪽이 이긴다.** 예외 없다.

```
1. R1   대상 문서가 아니면 무조건 배제
2. R11  질문이 묻는 층(목록/상세/집계)이 아니면 배제
3. R2-1 그 사실을 진술하지 않으면 배제
4. R2   진술하면 절이 어디든 포함
5. R8   한 조각으로 사실이 성립하지 않으면 짝으로 포함
6. R5   사실 일부만 있으면 있는 것만 포함
7. R10  기준답변에 없는 내용이 더 있는 건 배제 사유가 아님
```

**R2(포함)는 R11·R2-1(배제)를 무효화하지 못한다.** 이게 v4의 최대 결함이었다 —
"어느 절이든 정답"이 만능 열쇠로 쓰여 배제 규칙을 매번 뚫었다.

---

# 절차

## 1단계 — 기준답변을 사실 조각으로 분해한다

**분해 입도가 이후 모든 판단을 결정한다.** 다음 규칙으로 나눈다.

> **한 조각 = 독립적으로 참·거짓을 물을 수 있는 최소 단위.**
> 하나의 값, 하나의 요구, 하나의 대상.

```
기준답변: "사업기간은 계약일로부터 3개월이며, 안정화기간 1개월이 포함된다."
    → ① 사업기간 = 계약일로부터 3개월
    → ② 안정화기간 1개월 포함
```

**열거는 한 조각으로 묶는다.** 기준답변이 여러 단계·항목을 나열하면 그 나열 전체가 한 조각이다.

```
기준답변: "수요조사·사전협의·공고·심사요청·계획수립·…·실적관리를 지원해야 한다"
    → ① 위 프로세스 전 단계 지원          ← 한 조각. 단계마다 쪼개지 마라
```

이유: 단계별로 쪼개면 각 단계를 언급한 청크가 전부 "사실 조각을 온전히 담은" 것이 되어
정답이 폭주한다. 열거를 통째로 담은 청크만 그 사실을 말할 수 있다.

**분해 결과가 5조각을 넘으면 과분해다.** 다시 묶어라.

## 2단계 — 후보 전체를 훑는다

**처음부터 끝까지 읽어라.** 상위 몇 개만 보고 끊지 마라.
각 사실마다 그것을 진술한 청크 번호를 전부 적는다.

## 3단계 — 우선순위 순으로 걸러낸다

R1 → R11 → R2-1 순으로 배제하고, 남은 것에 R2를 적용한다.

## 4단계 — 자가 점검표를 통과시킨다

---

# R1. 대상 문서가 아니면 배제한다

후보에는 **다른 사업의 청크가 섞여 있다.** 검색에 문서 필터가 없기 때문이다.

각 후보의 `doc_id`를 `target_doc_id`와 대조하고, 다르면 내용이 아무리 그럴듯해도 버린다.

**비교는 정규화해서 하라.** 문자열이 정확히 같기를 기대하지 마라 — 이 프로젝트에는
골든셋과 인덱스의 `doc_id` 표기가 달라 직접 비교하면 매칭이 0건이 되는 함정이 있다.

정규화 절차:
1. 유니코드 NFC 정규화
2. `.hwp` `.pdf` 등 확장자 제거
3. 앞뒤 공백 제거, 연속 공백을 하나로
4. `(협상)` `(긴급)` `(재공고)` 같은 말미 괄호 표기 제거

정규화 후에도 안 맞으면 그때 배제한다.

> 사람이 라벨링했을 때 타 문서 혼입이 3건 나왔다. 화면에 문서명이 없어서다.
> 너는 `doc_id`가 보이므로 변명의 여지가 없다.

# R11. 질문이 묻는 층에 맞춘다

RFP는 같은 주제를 **여러 층**으로 기술한다. 질문이 어느 층을 묻는지 보고 그 층만 고른다.

| 층 | 무엇인가 |
|---|---|
| **집계** | 총합·건수·합계 행 |
| **목록** | 항목 일람 (고유번호 ↔ 명칭 매핑) |
| **상세** | 항목별 요구 내용 |
| **서술** | 사업개요·과업범위의 산문 기술 |
| **평가** | 제안서 평가 배점표·평점표 |

| 질문이 묻는 것 | 고를 층 |
|---|---|
| "총합은 / 몇 건인가" | **집계만.** 항목 나열 조각은 집계값을 진술하지 않는다 |
| "어떤 항목들이 있나" | **목록.** 개별 항목의 상세는 다른 층 |
| "X 항목은 무엇을 요구하나" | **상세.** 목록표는 명칭만 있어 답이 못 된다 |
| "고유번호 X의 명칭은" | **목록과 상세 둘 다** — 양쪽이 그 매핑을 담는다 |
| "무엇을 해야 하나 / 어떤 기능인가" | **서술·상세.** 평가 배점표는 아니다 |
| "배점은 몇 점인가 / 어떤 평가항목이 있나" | **평가.** 이때만 배점표가 정답이다 |

**평가 배점표는 질문이 배점·평가항목을 직접 물을 때만 정답이다.**
"제조사 지원을 어떻게 해야 하나"에 평가표의 "제조사 기술지원 | 5점" 행을 넣으면 안 된다.
그 청크를 받은 사람은 "그런 항목을 5점으로 평가한다"라고 말하지, "그렇게 지원해야 한다"라고 말하지 못한다.

# R2-1. 그 사실을 진술하지 않으면 배제한다

**배제 사유는 "다른 절에 있어서"가 아니라 "그 사실을 진술하지 않아서"다.**

## 항상 배제하는 것

| 배제 대상 | 왜 |
|---|---|
| **집계값 ↔ 내역** 이 어긋난 것 | 총계를 보고 항목별 값을 말할 수 없다. 반대도 마찬가지 |
| **상위 개념으로 뭉뚱그린 진술** | "모든 시설물의 상태 관리"는 "계측장비와 예경보시설"을 특정하지 않는다 |
| **선행 사업·선행 연구**의 목적·필요성 | 이번 사업의 요구가 아니다. 대상이 다르다 |
| **존재 언급만 있고 값이 없는 것** | "그 항목이 있다"와 "그 값이 얼마다"는 다른 사실 |
| **식별자만 있고 값이 없는 조각** | 그것만 받으면 아무 사실도 말할 수 없다 (예외는 R8) |
| **주어 없는 각주·단서 조항 단독 조각** | "상호협의로 변경 가능"만 있는 청크로는 질문에 답할 수 없다 |
| **값이 비어 있는 서식 표** | 제안서 서식의 공란은 값이 아니다 |
| **참조 안내문** | "제출기한: 입찰공고문 참조"는 기한을 진술하지 않는다 |

## 배경·목적·필요성 — 조건부다

**질문이 "무엇을 해야 하나"를 물으면 배제한다.** 배경 절은 요구를 진술하지 않는다.

**질문 자체가 목적·기대효과·배경을 물으면 그 절이 정답 층이다.** 이때는 R11이 우선한다.

```
"이 시스템은 무엇을 해야 하나요?"      → 배경 절 배제
"이 사업의 기대 효과는 무엇인가요?"     → 기대효과 절이 정답 층
```

단 "기대 효과"를 물어도 **선행 연구의 필요성 서술**은 여전히 배제한다(대상이 다르다).

# R2. 그 사실을 진술하면 절이 어디든 포함한다

RFP는 같은 사실을 여러 곳에 반복 진술한다. 구조적으로 그렇다.

| 중복 유형 |
|---|
| 사업개요 ↔ 제안요청 개요 |
| 과업내용 ↔ 요구사항 명세(SFR/ECR/COR/PSR) |
| 요구사항 총괄표 ↔ 상세 요구사항 |
| 본문 ↔ 부록 서식 안에 재기재된 사업내용 |

**전부 고른다.** 검색이 어느 쪽을 가져와도 답이 되기 때문이다.
"어느 쪽이 더 정확한가"는 이 작업이 답할 질문이 아니다.

**부록 서식이라도 실질 사실을 담으면 R2를 적용한다.** 서식이라는 이유만으로 빼지 마라.

## 상한

**정답은 최대 4개.** 5개 이상을 고르고 있다면 1단계에서 사실을 과분해한 것이다.
1단계로 돌아가 조각을 병합하고 다시 골라라.

**같은 사실이 5곳 이상에 흩어져 있으면**(계약 서식의 사업명·발주기관 등) 그중 2개만 고른다.
고를 기준:
1. 질문의 핵심 낱말이 그대로 나오는 것
2. 본문 절(사업개요·과업내용) > 부록 서식
3. 값이 온전한 것 > 잘린 것

# R8. 한 조각으로 성립하지 않으면 짝으로 포함한다

500자 경계가 표 중간을 자르는 일이 잦다. 번호가 연속인 청크가 한 표에서 갈라졌다면,
기준답변의 사실이 양쪽에 나뉘어 있는지 확인하라.

**한쪽만으로 사실이 성립하지 않을 때만 둘 다** 고른다.

**값 조각이 단독으로 식별 가능하면 식별자 조각을 넣지 마라.**
값 조각에 그 대상 고유의 사양이 들어 있어 어느 항목인지 알 수 있으면, 식별자만 있는
조각은 R2-1(값 없는 조각)로 배제한다.

**이미 자기완결 청크가 따로 있으면** 쪼개진 짝은 R2의 중복으로 보고 함께 넣는다 —
단 상한(4개) 안에서, 자기완결 청크를 우선한다.

**표와 줄글이 비인접으로 갈린 경우**(번호가 연속이 아님)도 같은 원칙이다.
한쪽만으로 사실이 성립하지 않으면 둘 다 고른다. 번호 연속은 판단의 힌트일 뿐 조건이 아니다.

# R5. 사실 일부만 후보에 있으면 있는 것만 고른다

후보는 검색 결과라서 기준답변의 근거를 다 담지 못할 수 있다.

**빈 목록을 내지 말고** 후보에 있는 사실을 담은 청크를 고르고,
`uncovered`에 근거가 없던 사실을 적는다.

**인정 조건**: 기준답변의 **사실 조각 하나를 온전히** 담아야 한다.
조각의 일부·상위 개념·인접 값은 인정하지 않는다 (R2-1과 같은 잣대).

**어떤 사실 조각도 온전히 담긴 게 없으면 빈 목록**을 낸다.

# R6. 표기가 달라도 같은 값이면 정답이다

문서와 기준답변이 다른 표기법을 쓰는 일이 흔하다. **정규화해서 비교하라.**

| 기준답변 | 문서 | 판정 |
|---|---|---|
| `40,000,000원` | `40,000천원` | **같음** |
| `3.8억원` | `380,000,000원` | 같음 |
| `제2019-69호` | `행정안전부고시 제2019-69호` | 같음 |
| `210일` | `7개월` | 다름 — 근거 부족 |

금액은 단위(천원·백만원·억원)를 원으로 환산한 뒤 비교한다.
고시·규격 번호는 발행기관 접두어를 떼고 번호만 비교한다.

# R7. 서식이 깨져 있어도 내용으로 판단한다

hwp 추출 오류로 청크 머리에 **CJK 확장 한자 영역(U+3400~U+4DBF, U+F900~U+FAFF)** 문자가
붙는 경우가 있다. 한국어 RFP 본문에 정상적으로 등장할 수 없는 문자다. 무시하고 나머지를 읽어라.

마크다운 표가 파이프와 빈 칸투성이여도 **답이 그 안에 있으면 정답이다.**
서식이 아니라 내용으로 판단하라.

# R9. 거의 똑같은 청크는 식별자로 가린다

같은 양식의 표가 여러 벌 있는 문서에서는 잘린 조각들이 글자가 거의 같아진다.
이때 각 조각은 **서로 다른 대상**(다른 타입·다른 장비)을 가리키므로 R2의 중복이 아니다.

`섹션` 필드, `chunk_id` 순번, 그리고 **조각 안의 고유 수치**(크기·용량·성능값)로 특정하라.
앞 조각에 식별자가 있으면 그것으로 확정한다.

**특정이 불가능하면 고르지 마라.** 여럿 중 하나를 찍는 것은 오염이다.

**예외 — 기준답변이 동일성을 주장할 때.**
기준답변이 "N개 타입이 모두 같은 사양"이라고 진술하면, 그 N개 조각이 **전부 정답**이다.
이때는 특정이 목적이 아니라 동일성 확인이 목적이다.
후보에 일부 타입만 있으면 그것만 고르고 `uncovered`에 "나머지 타입 표 부재"를 적는다.

# R10. 기준답변에 없는 내용이 더 있는 건 배제 사유가 아니다

청크는 대개 기준답변보다 길다. 기준답변의 사실을 담고 있으면 정답이고,
그 외 내용이 더 있는 것은 문제가 아니다.

단 R11이 우선한다 — **층이 다르면 내용이 많아도 배제**다.

# 유형별 지침

## `단일세부` · `직답`
기본 절차 그대로. 직답에서 값이 `data_list.csv` 메타에만 있고 본문에 없으면 빈 목록.
참조 안내문("입찰공고문 참조")과 값이 빈 서식 표는 근거가 아니다.

## `후속`
`선행_턴`의 질문으로 대명사("그 사업")를 해소한 뒤 판단한다.
**채점표는 `expected`의 사실만이다** — 선행 턴의 답까지 덮을 필요는 없다.

## `탐색비교`
`대상_doc_id`가 리스트다. **문서마다 독립적으로** 절차를 돌리고 결과를 문서별로 낸다.

- R1은 "리스트에 있는 문서면 허용"으로 완화된다
- 상한(4개)은 **문서마다** 적용한다
- 어느 한 문서의 근거가 후보에 없으면 그 문서를 `uncovered`에 적는다
- 출력에 `gold_by_doc`을 함께 낸다 (아래 스키마)

## `모른다`
근거가 없어야 정상이다. 빈 목록이 기대값.

- **R5를 적용하지 마라.** 부분 근거를 찾아 넣지 마라
- 그럼에도 **후보 전체를 반드시 읽어라.** "없을 것"이라 가정하고 건너뛰면
  실제로 있는 근거를 놓친다 (사람이 이 실수를 했다)
- 근거가 정말 있으면 빈 목록 대신 그것을 고르고 `note`에 "모른다 유형인데 근거 발견"이라 적어라

## `반문`
대상 문서 자체가 없다. 항상 빈 목록.

# 출력 형식

문항마다 JSON 한 줄(JSONL):

```json
{"qid":"<입력 그대로>",
 "gold_chunk_ids":["<후보에 있는 chunk_id>"],
 "facts":["<1단계에서 분해한 사실 조각>"],
 "applied":["R11","R2-1","R8"],
 "reason":"<조각별로 어느 청크가 어느 사실을 진술하는지>",
 "uncovered":["<후보에 근거가 없던 사실 조각>"],
 "confidence":"높음|보통|낮음",
 "note":"<애매했던 지점. 없으면 빈 문자열>"}
```

`탐색비교`는 `gold_by_doc`을 추가한다:

```json
{"gold_by_doc":{"<doc_id>":["<chunk_id>"],"<doc_id2>":[]},
 "gold_chunk_ids":["<위를 합친 것>"]}
```

## `confidence` 판정 규칙 — 재량이 아니다

| 값 | 조건 |
|---|---|
| **낮음** | `uncovered`가 비어 있지 않다 · 또는 R9로 대상을 특정하지 못했다 |
| **보통** | 어느 청크를 넣을지 규칙만으로 결정되지 않아 판단이 개입했다 · 또는 상한(4개)에 걸려 잘라냈다 |
| **높음** | 위 어느 것도 아니다. 규칙 적용만으로 결과가 나왔다 |

**`note`가 비어 있지 않으면 `높음`을 쓸 수 없다.**

# 제출 전 자가 점검

문항마다 확인한다. **하나라도 걸리면 고치고 다시 확인하라.**

- [ ] `gold_chunk_ids`의 모든 id가 **후보 목록에 문자 그대로 존재**하는가
      ← 번호 하나 틀리면 오답 1건 + 누락 1건, 손해가 두 배다
- [ ] 후보를 처음부터 끝까지 읽었는가
- [ ] 고른 청크의 `doc_id`가 전부 대상 문서인가 (R1, 정규화 후 비교)
- [ ] 질문이 묻는 층과 고른 청크의 층이 같은가 (R11)
- [ ] 고른 것 하나하나가 **그것만 보고 기준답변의 사실을 말할 수 있는가** (R2-1)
- [ ] 5개 이상 골랐다면 1단계 분해로 돌아갔는가 (R2 상한)
- [ ] 같은 사실을 진술하는데 절이 다르다는 이유로 뺀 게 없는가 (R2)
- [ ] 사실 일부만 있는데 빈 목록으로 내지 않았는가 (R5)
- [ ] `confidence`를 규칙표대로 매겼는가
- [ ] 빈 목록으로 낸 문항은 후보 전체를 다 읽고 없다고 판단한 것인가

## 마지막 — 문서 단위 일관성 점검

**같은 `target_doc_id`를 가진 문항들을 마지막에 함께 훑어라.**
같은 청크를 한 문항에서는 정답, 다른 문항에서는 오답으로 판정했다면
둘 중 하나가 틀렸다. 둘 다 다시 보고 근거를 맞춰라.
