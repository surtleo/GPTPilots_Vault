## 0. 왜 다시 재나 — 이전 판의 결론은 "판정 불가"에 가까웠다

이전 판 실험은 임베딩 축을 "현행 유지"로 닫았지만, 같은 문서에는 이런 자기비판이 남아 있었다.

> 승격 기준이 **측정 해상도보다 낮다.** 지금 문항 수로는 경계 효과를 안정적으로 판정하기 어렵다.

즉 이전 판의 "현행 유지"는 **"바꿔서 좋아지지 않는다"가 아니라 "좋아지는지 알 수 없다"**에 가까웠다.
이 실험은 그 해상도 부족을 문항 수로 메우고, 동시에 **새 후보(LoRA-GPL 파인튜닝 e5)**를 넣어 다시 판정한다.

### 새로 들어온 후보 — gpl3

팀에서 e5-small을 RFP 도메인에 GPL(Generative Pseudo Labeling)로 파인튜닝한 LoRA 어댑터가 나왔다
(`intfloat-multilingual-e5-small-LoRA-gpl3.pt`). 병합 상태를 먼저 검증했다.

| 확인 | 결과 |
|---|---|
| state_dict 키 | 199개, missing/unexpected **0** |
| 단어 임베딩 | `(250037, 384)` — 베이스와 동일 |
| 변경된 텐서 | **72개 / 12개 레이어** (어텐션·FFN만) |
| 임베딩·풀러 | **변경 없음** |

→ 어댑터가 **실제로 병합된 가중치**다. 임베딩 층이 안 바뀌었으므로 **e5의 `passage:`/`query:` 프리픽스 규약을 그대로 써야 한다**(§6).

## 2. 조작 변인 — 임베딩 4종

| 코드 | 모델 | 파라미터 | 차원 | 성격 |
|---|---|---|---|---|
| **M0** | `intfloat/multilingual-e5-small` | 118M | 384 | **현행 기준선** |
| M1 | `BAAI/bge-m3` | 568M | 1024 | 대형 다국어 |
| M2 | `nlpai-lab/KURE-v1` | 0.6B | 1024 | 한국어 특화 |
| **M3** | e5-small + LoRA-GPL merged (gpl3) | 118M | 384 | **도메인 파인튜닝** |

**핵심 비교쌍은 M0 ↔ M3다.** 같은 계열·같은 차원·같은 프리픽스라 다른 교란 없이
**도메인 학습 효과만** 분리된다. M1·M2는 v5 판정(6.8.9)의 재확인용이다.

## 3. 지표

| 지표 | 역할 |
|---|---|
| **MRR@10** | **판정 지표** — 첫 정답의 순위 |
| nDCG@10 | 상위권 전체의 질 |
| Recall@5 | LLM에 실제로 넘어가는 5개의 질 |
| Recall@20 | 리랭커가 손댈 수 없는 **상한** |

> [!warning] MRR 하나만 보면 놓친다
> v5의 BM25 판정이 실제로 그랬다 — MRR로는 유의차 없음인데 nDCG·Recall@5로는 **유의하게 나빴다**.
> 판정 지표를 하나만 두면 반대 방향의 손해가 안 보인다.

## 4. 통계 — 문서 클러스터 paired bootstrap

같은 문서에서 뽑은 문항들은 독립이 아니다. 문항 단위로 재표집하면 유효표본을 과대평가해
**CI가 실제보다 좁아진다 — 유의성을 부풀리는 방향의 오차다.**

- 군집 키: **첫 대상 문서**
- 실측: 251문항 → **95군집 / 군집당 2.64문항**
- 효과: 문항 단위 대비 CI 폭 **+8.4%** (설계효과와 부합)

## 5. 승격 기준 — 측정 전에 코드로 고정한다

```
CI 하한 > 0  AND  점추정 ≥ +0.03  AND  어떤 유형도 −0.03 이하 회귀 없음
```

`scripts/verdict_12_7.py`에 **수치를 보기 전에** 박아 넣었다.
수치를 보고 나서 기준을 고르면 어떤 결과든 정당화된다.

> [!important] 동점 통과 시의 규칙
> 여러 구성이 통과하면 **작은 쪽을 고른다.** 인덱스 크기·질의 비용이 그만큼 낮기 때문이다.
> 다만 이번에는 평균 성능·견고성·유형 안정성·모델 크기가 서로 다른 답을 가리킨다.
> 따라서 이 규칙의 적용 여부는 [[검색 실험 결과 (v6 4모델)]] §6의 **사용자 결정 대기** 항목으로 남긴다.

## 6. ⚠️ 프리픽스 — 이 실험에서 제일 위험한 통제 항목

e5 계열은 학습 때 `passage: ` / `query: ` 접두사를 붙였다. 안 붙이면 성능이 무너진다.
gpl3는 **임베딩 층이 안 바뀐 e5 파생**이므로 같은 규약을 따라야 한다.

```python
# src/index/chunk.py:48
def build_passage_prefix(meta, section):
    return f"passage: [사업명: {...} / 발주기관: {...} / 섹션: {section}]\n"
```

**게이트 방식**: 육안 확인이 아니라 **전수 복원 검사**를 썼다.
인덱싱에 실제로 들어간 문자열을 되짚어 재임베딩한 벡터와 저장된 벡터의 코사인을 전건 비교 —
**min 0.9999999 / mean 1.0**. 육안 샘플링보다 강한 증명이다.

## 7. 정답지 — 골든셋 v6를 왜 새로 만들었나

v5 정답지는 **3모델(M0·M1·M2) 합집합 풀**에서 판정됐다.
여기에 M3를 그냥 얹으면 **M3만 데려온 후보는 판정된 적이 없어 전부 오답으로 세어진다.**
모델을 추가하면서 정답지를 안 고치면 **새 모델에게만 불리한 잣대**가 된다(6.8.8에서 이미 겪은 사고).

그래서 두 갈래로 채웠다.

| 갈래 | 대상 | 무엇을 판정했나 |
|---|---|---|
| **신규 85문항** | v6에 새로 들어온 문항 | **4모델 합집합 후보** 전건 |
| **기존 169문항 델타** | v5부터 있던 문항 | **M3 고유 신규 후보만** (기존 정답은 맥락으로 동봉) |

### 라벨링 파이프라인 — 2단계

1. **라벨러** — `r8/SKILL.md` (재현율 0.863 / 정밀도 0.750)로 원문 대조 판정
2. **독립 검증자** — `VERIFY_SPEC.md` 규격으로 라벨러가 고른 정답만 재검사

> [!note] 왜 같은 스킬을 계속 쓰나
> 증분을 더 엄격한 방법으로 라벨링하면 기존 정답과 잣대가 갈린다.
> **편향을 다른 편향으로 바꾸는 꼴**이라 기존 200문항과 동일 스킬·동일 프롬프트를 유지했다.

실측 결과: 검증에서 **제거 2건 / 추가 8건** — 제거보다 추가가 많은 것이
라벨러 스킬 프로필(재현율 높고 정밀도 낮음)과 방향이 맞는다. 2단계가 설계대로 작동했다.

> [!warning] 팀 OpenAI API 미사용
> 골든셋 판정·라벨링은 전부 Claude가 직접 수행했다(팀 한도 $20 보호). `judge=gpt-5-nano` 경로는 골든셋에 안 돌렸다.

### v6 최종 구성

| | 문항 | 정답 |
|---|---|---|
| 기존 g200 계열 | 169 | — |
| 신규 g300 계열 | 85 (채점 성립 82) | — |
| **합계** | **254 → 채점 성립 251** | **486건** |

유형 분포는 두 구간이 거의 같다(단일세부 53% vs 54%, 후속 18% vs 18%).

> [!important] 절대값은 v5와 직접 비교 불가
> 정답지가 바뀌어 **nDCG·Recall은 분모 영향을 받는다.**
> 비교는 반드시 **같은 v6 기준의 모델 간 델타**로 한다.

병합은 **집합 연산**으로 했다. 리스트로 이으면 중복 chunk_id가 두 번 들어가 분모가 부풀고
채점이 조용히 틀어진다 — 실제로 델타 판정에서 중복 2건이 나왔고 여기서 제거됐다.

## 8. 측정이 성립하려면 — 게이트 3종

| # | 게이트 | 검사 |
|---|---|---|
| 1 | **청크 경계 동결** | 모델 간 chunk_id 차집합 0건 |
| 2 | **프리픽스** | 전수 복원 코사인 ≥ 0.9999999 (§6) |
| 3 | **동일 엔진** | 전 모델 같은 검색 엔진 |

> [!note] 게이트 3은 종단에서는 사실상 무의미했다 — 그러나 사전에는 알 수 없었다
> M0를 근사 엔진(fast)과 정확 엔진(exact) 두 벌로 만들어 비교했더니
> **종단 MRR 차이가 251문항 전건 0.000000**이었다. 리랭커가 후보를 전량 재정렬하므로 씻긴다.
> §8-3은 **dense 단독 측정에서만 구속력이 있다.** 결과적으로 두 벌은 불필요했지만,
> 그 사실은 측정으로만 알 수 있었다.

## 10. 채택 판단 축 — 아직 결정하지 않는다

승격 판정은 "올릴 수 있다"를 말한다. "무엇을 올릴지"는 별도 결정이다.
이번 결과는 한 줄 결론으로 접기 어렵다.

| 판단 축 | 가리키는 모델 | 왜 그렇게 보나 |
|---|---|---|
| 평균 성능 | **M2 KURE-v1** | MRR@10 델타가 가장 크다 |
| 견고성 | **M2 KURE-v1** | 기존 g200·신규 g300 구간에서 일관되게 버틴다 |
| 유형별 최저치 안정성 | **M3 gpl3** | 최저 유형도 승격 기준의 회귀 한계와 거리가 있다 |
| 모델 크기·운영비 | **M3 gpl3** | 118M·384차원으로 M1·M2보다 약 5배 작다 |

> [!warning] 사용자 결정 대기
> §5의 "여러 구성이 통과하면 작은 쪽" 원칙은 gpl3를 가리키지만,
> 평균 성능·견고성은 KURE-v1을 가리킨다.
> **ADR-010 신설이나 `spec.md` §2 개정은 이 문서의 범위가 아니다.**
> 사용자 결정 이후에 한다.
