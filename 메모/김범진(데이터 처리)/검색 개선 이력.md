# 검색 개선 이력

이 프로젝트에서 검색(리트리벌)을 여태 어떻게 고쳐왔는지의 시간순 기록. 파이프라인 현재 모습은
[[온라인 쿼리 파이프라인]], 남은 개선 후보는 [[쿼리 파이프라인 개선안]], 개념 배경은
[[쿼리 파이프라인 개념 정리]], 진행 중 작업 상세는 [[검색 품질 개선 (BM25·리랭커)]] 참고.

## 1. 최초 구현 — dense 단독 + 폴백 금지 (`9be7c5d`, 07-15)

- **문제**: 검색 자체가 없던 상태. spec §6-2가 요구한 최소 검색 경로 구축.
- **어떻게**: `query: ` prefix 임베딩(e5)으로 chunks 컬렉션 top-k. 문서가 특정되면
  `where={"doc_id": ...}` 메타 필터. **필터 후 0청크면 빈 목록 반환** — 필터를 풀고 전체
  재검색하는 폴백을 금지(spec §12-3)해서 "다른 문서 내용을 그 문서 답인 척" 하는 오염을 차단.
  고정 응답 처리는 호출부(CLI/라우터) 책임으로 분리.
- **함께**: `format_context`가 히트마다 `[출처: 사업명 / 섹션]` 라벨을 붙여 근거 표기의 기반 마련.
- 위치: `src/query/retrieve.py:16` (retrieve), `src/query/retrieve.py:59` (format_context).

## 2. 관측 가능성 — LangSmith 트레이싱 (`6019d47`, 07-15)

- **문제**: 검색이 어떤 청크를 몇 개, 어떤 distance로 돌려주는지 볼 수단이 없어 품질 논의가 감이었음.
- **어떻게**: `traced()` 지연 데코레이터로 `retrieve`를 `run_type=retriever` span으로 기록.
  NDA 가드(ADR-007)로 `hide_inputs/hide_outputs` 코드 강제 마스킹 — 스칼라 메타만 통과.
  (이후 07-25 사용자 지시로 `LANGSMITH_MASK_TRACES=False` 전환.)
- 검색 로직 자체는 무변경(+2줄) — 이후 개선들이 "측정 후 판단"이 되게 한 토대.

## 3. Parent-Document — 쪼개진 큰 표 복원 (`14d018f`, 07-24)

- **문제**: CHUNK_SIZE를 넘는 큰 표가 여러 조각으로 쪼개지면 검색엔 조각 하나만 걸려 답변이
  표의 절반만 반영됨(실측 확인). 표 청크 5,411개 중 2,758개(51%)가 쪼개진 표였음.
- **어떻게**: 청킹에서 2조각 이상으로 쪼개진 표에만 원본 표 전체를 `parent_text` 메타로 동봉.
  **검색 단위는 조각 그대로**(정밀도 손실 없음), `format_context`가 렌더할 때만 조각 대신 표
  전체를 넣고, 같은 `parent_text` 중복 히트는 1회만 삽입.
- **효과**: 넓은 질문(표 전체 필요)·좁은 질문 양쪽 의도대로 작동. 기존 테스트 296개 전건 통과.
- 위치: `src/query/retrieve.py:59` (format_context의 parent_text 분기), `src/index/chunk.py`.

## 4. LCEL 전환 — LangChain 표준화 (`6866d9c`, 07-25)

- **문제**: raw Chroma 호출이라 LangSmith 트레이스가 커스텀 함수 덩어리로만 보였고, LC 생태계
  컴포넌트(리트리버 교체·체인 조합)를 쓸 수 없었음.
- **어떻게**: `src/query/lc.py` 신설 — `E5Embeddings`(query:/passage: prefix 래핑,
  `src/query/lc.py:36`), `build_retriever`(`src/query/lc.py:74`, doc_id 필터 유지),
  `doc_to_hit`(`src/query/lc.py:89`, 기존 hit 스키마로 변환). `retrieve()`는
  `VectorStoreRetriever.invoke` 호출로 교체.
- **핵심 제약**: **검색 결과·생성 계약 불변** — 실인덱스 top-5·doc_id 필터 파리티 확인,
  347 테스트 통과. 리팩터이지 품질 변경이 아님. 부작용: as_retriever(similarity) 경로는
  점수를 안 돌려줘 `distance=None`이 됨 (소비처가 관측 요약뿐이라 수용).

## 5. 문서 메타 헤더 부착 (`4684beb`, 07-27, #16)

- **문제**: [[쿼리 파이프라인 개선안]]의 1번(메타·본문 융합) 실행. CSV 확정값(금액·마감일·기관)이
  청크 metadata로 이미 인덱싱돼 있는데 `format_context`가 라벨에 사업명·섹션만 적어 생성 LLM이
  볼 수 없었음 → 복합 질문에서 예산·마감일 누락.
- **어떻게**: 히트를 doc_id로 묶어 **문서당 1회** `[문서 정보(출처: data_list.csv) — …]` 헤더 부착
  (`src/query/retrieve.py:42` `_doc_header`). 금액은 `3.8억원(380,000,000원)` 억 단위 병기로
  자릿수 오독 방지 (`src/query/retrieve.py:31` `_format_amount`). 헤더 출처를 명시해 LLM이
  무관한 본문 섹션을 출처로 인용하는 것도 차단.
- **효과 (실측 40건)**: 컨텍스트에 사업금액 포함 21/60 → 57/60, 입찰마감 포함 0/60 → 51/60
  (마감일은 본문에 아예 없어 기존엔 답변 불가). 비용은 프롬프트 +23토큰(+4.2%), 턴당 +$0.000006.
  재인덱싱 불필요, LLM 추가 호출 0회.

## 6. 진행 중 — 하이브리드 검색 + 리랭커 (`feat/hybrid-rerank`, 미반영)

상세는 [[검색 품질 개선 (BM25·리랭커)]]. 20커밋 / 12파일 / +1,752줄, 406테스트 통과.

- **계기**: 실험 6.1의 6개 변형 전부에서 `hit@5`가 1.000 포화 → 검색을 뭘 바꿔도 효과를 잴 수
  없었음. 원인은 청킹이 모든 청크에 `사업명+발주기관` 접두를 붙여 **문서 단위** 적중이 항상
  성공하기 때문. 문서는 늘 맞히니 문서 지표는 죽은 지표.
- **1단계 — 자 먼저 만들기**: 청크 단위 순위 지표 신설 — MRR@10·nDCG@10·Recall@5
  (`src/eval/ir_metrics.py:14,28,36`).
- **2단계 — 검색 변형**: `src/query/hybrid.py` 신설 — RRF 융합(`hybrid.py:21`),
  kiwipiepy 형태소 토큰화 한국어 BM25(`hybrid.py:56,144`), 크로스인코더 리랭커
  BAAI/bge-reranker-v2-m3(`hybrid.py:233`, 실패 시 원순위 폴백).
- **배선**: `retrieve()`가 config 플래그로 분기(worktree `src/query/retrieve.py:18`).
  **기본값 둘 다 False → 기존 dense 경로와 결과가 바이트 단위로 동일**하도록 조기 반환으로
  고정(회귀 테스트로 못 박음). `doc_id` 필터 시 BM25는 건너뜀 — 후보가 한 문서로 좁혀져 어휘
  검색 이득이 없고 BM25 인덱스가 메타 필터를 미지원. 리랭커는 적용.
- **승격 기준 (측정 전 확정)**: 베이스라인 대비 전체 MRR@10 **+0.05 이상** AND 기존 문항 hit@5
  1.0 유지 → 플래그 ON. 미달 시 미채택 기록 후 코드는 OFF 유지. 여러 변형이 통과하고 차이가
  0.02 이내면 더 단순한 쪽 채택.

## 검색 품질을 갉아먹는 미해결 문제

1. **요구사항 표 청크의 ID 유실**: 청크 4,895개 중 1,450개(30%)에 고유번호(SFR-03 등)가 없음.
   세로형 키-값 요구사항 표가 500자에서 잘리며 ID 행이 앞 청크에 남는 구조. 라벨링 때 "정답이
   안 보인다"의 원인. 현재 다른 세션에서 청킹 수정 + 재인덱싱 진행 중.
2. **실험 러너의 doc_id 정규화 누락**: `scripts/run_experiments.py:125`에 `_norm_doc_id`가 빠짐 —
   골든셋 doc_id는 `.hwp` 확장자를 달고 있는데 인덱스는 `make_doc_id()` 출력이라 직접 비교하면
   0건 매칭. `src/eval/run_eval.py:199`에는 정규화가 있음. 이번 작업 범위 밖이라 미수정.
3. **플래그 ON 전 선결 — 동시성**: `src/api/server.py`의 `ask()`가 동기 함수라 FastAPI 스레드풀
   동시 요청 시 모듈 캐시(리랭커 568M 모델·BM25 인덱스)가 중복 로드될 수 있음 → L4 GPU OOM
   위험. 락 필요.

## 관통하는 원칙

- **검색 단위와 렌더 단위를 분리**한다 — Parent-Document(3)·메타 헤더(5) 모두 인덱스는 안 건드리고
  `format_context`만 고쳐 재인덱싱 0회로 해결.
- **결과 계약 불변을 테스트로 못 박고** 바꾼다 — LCEL 전환(4)의 파리티 확인, 하이브리드(6)의
  플래그 OFF 동일성 회귀 가드.
- **자(지표)가 죽었으면 검색보다 자부터** 고친다 — hit@5 포화 → 청크 단위 지표 신설(6).
