# 검색 실험 설계

> **무엇을 어떻게 재는가.**
> 성적과 판정 숫자는 [[검색 실험 결과]]가 정본이다. 이 문서는 조건과 읽는 법만 고정한다.

> [!note] 먼저 읽을 결론
> 이 실험은 **"올바른 공고 문서가 이미 정해졌다"**는 전제에서, 그 문서 안의 정답 청크를 몇 등으로 찾는지 잰다.
> 따라서 [[검색 실험 결과]]의 MRR 0.7443은 **문서 선택까지 포함한 전체 서비스 점수**가 아니다.

---

## 0. 한눈에

### 질문 하나가 지나가는 길

```
질문
  ↓
① 문서 선택: 어느 공고인가
  ↓
문서 1개
  ↓
② 후보 추출: 청크 20~35개를 뽑음
  ↓
③ 리랭커: 후보를 다시 줄세움
  ↓
④ 상위 5개를 LLM에 전달
```

이번 실험이 제대로 재는 곳은 **② 후보 추출**과 **③ 리랭커**다.
① 문서 선택은 골든셋의 `대상_doc_id`를 그대로 쓰므로 **맞았다고 가정**한다.

| 단계 | 이 실험에서의 취급 | 왜 중요한가 |
|---|---|---|
| 문서 선택 | 거의 미측정 | 라우팅 정확도 표본은 13건, 정확도 0.769뿐 |
| 청크 검색 | 주 측정 대상 | 같은 문서 안에서 정답 문단을 찾는 능력 |
| 리랭킹 | 주 측정 대상 | 뽑힌 후보 20개를 답변에 유리한 순서로 재정렬 |
| 답변 생성 | 미측정 | LLM이 실제로 맞게 답하는지는 별도 실험 |

> [!warning] 측정 범위의 한계
> 웹에서는 사용자가 목록에서 공고를 클릭하면 `doc_id`가 정해진다.
> 라우터가 문서를 못 잡으면 전체 검색으로 넘어가지 않고 되묻는다(`spec §12-3` 폴백 금지).
> 그래서 이 실험의 점수는 **"올바른 공고를 골랐다"는 전제 위의 청크 검색 점수**다.

### 처음 나오는 용어

| 용어 | 한 줄 뜻 |
|---|---|
| **청크** | 문서를 잘라 놓은 문단 하나. 검색과 채점의 최소 단위 |
| **임베딩** | 문장을 숫자 벡터로 바꾸는 모델 |
| **dense 검색** | 임베딩 벡터가 가까운 청크를 찾는 의미 검색 |
| **[[BM25]]** | 단어가 얼마나 겹치는지로 찾는 어휘 검색 |
| **하이브리드 검색** | dense와 BM25 후보를 섞는 검색 |
| **[[크로스인코더 리랭커\|리랭커]]** | 질문과 후보를 하나씩 비교해 후보 순서를 다시 매기는 모델 |
| **[[MRR]]@10** | 정답 청크가 10등 안에서 몇 등인지 평균낸 지표. 1등이면 1.0, 2등이면 0.5 |
| **골든셋** | 사람이 판정해 둔 질문·정답 청크 묶음 |
| **풀링 편향** | 한 모델이 찾은 후보만 라벨링해서, 다른 모델이 새로 찾은 정답을 오답으로 세는 편향 |

## 1. 무엇을 고정하나

하나라도 바뀌면 이전 숫자와 비교할 수 없다.

| 고정 항목 | 값 | 이유 |
|---|---|---|
| 질문셋 | 200문항 중 채점 성립 164문항 | 모른다·반문·빈 정답은 검색 점수로 채점할 수 없음 |
| 정답지 | 골든셋 v5 | 정답 청크와 판정 풀이 조합마다 같아야 함 |
| 검색 범위 | 대상 문서 안 `doc_id` 필터 | 정부 RFP는 서로 문장이 비슷해 문서를 안 좁히면 엉뚱한 공고가 올라옴 |
| 청크 경계 | e5 토크나이저 기준 | `chunk_id`가 문서 내 위치 기반이라 경계가 밀리면 정답지가 깨짐 |
| 캐시 엔진 | 세 임베딩 모두 `fast` | 검색 엔진이 다르면 모델 성능이 아니라 엔진 차이를 재게 됨 |
| 판정 지표 | [[MRR]]@10 | 정답 청크가 답변 컨텍스트 앞쪽에 오는지 보기 위함 |
| 통계 | [[paired bootstrap]] 95% CI, 1만 회, 시드 `20260729` | 소표본 노이즈를 평균 상승으로 오판하지 않기 위함 |

정답지의 구체 숫자와 판정 결과는 [[검색 실험 결과]] §2가 정본이다.

## 2. 무엇을 바꾸나

| 축 | 코드 | 후보 | 설명 |
|---|---|---|---|
| 임베딩 | `M0` | `intfloat/multilingual-e5-small` | 현행. 작고 빠름 |
| 임베딩 | `M1` | `BAAI/bge-m3` | 큰 다국어 모델 |
| 임베딩 | `M2` | `nlpai-lab/KURE-v1` | bge-m3의 한국어 튜닝판 |
| 리랭커 | `R1` | `BAAI/bge-reranker-v2-m3` | 현행 |
| 리랭커 | `R2` | `dragonkue/bge-reranker-v2-m3-ko` | R1의 한국어 튜닝판 |
| 후보 구성 | `C_doc` | dense 20개 | 현행 기준선 |
| 후보 구성 | `D_doc` | dense 20개를 앞단에서 재정렬 | 리랭커 뒤에서는 C와 동치라 실험값 해석 불가 |
| 후보 구성 | `E_doc` | dense와 BM25를 섞어 상위 20개 | BM25 추가와 dense 제거가 섞임 |
| 후보 구성 | `F_doc` | dense와 BM25를 섞어 상위 30개 | E보다 후보 예산을 늘림 |
| 후보 구성 | `G_doc` | dense 20개 + BM25 20개 전부 | BM25 후보를 빼지 않고 더하는 핵심 변형 |

접미사 규칙은 단순하다.

| 접미사 | 뜻 | 판정에 쓰나 |
|---|---|---|
| `_doc` | 대상 문서 안에서만 검색 | 예 |
| `_full` | 전체 문서에서 검색 | 현재 판정 기준 아님 |

## 3. 왜 후보 구성을 먼저 재나

리랭커와 임베딩은 **후보 안에 들어온 청크만** 다룬다.
후보 구성이 바뀌면 리랭커·임베딩 판정의 전제가 바뀐다.

| 순서 | 하는 일 | 이유 |
|---|---|---|
| 1 | 후보 구성 C/D/E/F/G 비교 | BM25를 후보 공급자로 쓸지 먼저 결정 |
| 2 | 확정된 후보 위에서 R1/R2 비교 | 리랭커는 후보 집합을 바꾸지 않음 |
| 3 | 확정된 후보·리랭커 위에서 M0/M1/M2 비교 | 임베딩 교체는 재인덱싱 비용이 큼 |

> [!warning] 현재 상태
> 후보 구성 C/D/E/F/G × 임베딩 3종 × R1 측정은 **진행 중**이다.
> 특히 새 실행의 m0 `C_doc`이 0.7373으로 나오는데, 기존 정본은 0.7443이다.
> 원인은 아직 모른다. 정답지 v4→v5 갱신도 아니고, 별도 재실행 비결정성도 아니다.
> 따라서 `G_doc`의 잠정 +0.022는 **아직 신뢰하면 안 된다**.

## 4. BM25를 어떻게 읽어야 하나

기존 구현은 BM25가 찾은 청크의 **본문을 가져오지 않았다**.
`retrieve.py`에는 "추가 Chroma 왕복이 필요해 v1 범위 밖"이라는 판단이 남아 있었다.

그 결과 BM25는 후보를 넓히지 못하고 **순서만 바꾸는 반쪽 구현**이 됐다.
뒤에서 리랭커가 다시 줄세우므로, 이 역할은 리랭커가 덮어쓴다.

| 말하면 안 되는 결론 | 정확한 결론 |
|---|---|
| 어휘 검색은 쓸모없다 | **후보를 안 넓히는 BM25 구현은 쓸모를 보이지 못했다** |
| BM25는 비싸서 못 쓴다 | 본문 조회 실측은 20개 0.6ms라 이 근거는 약하다 |
| BM25는 이미 검증 끝났다 | 후보를 실제로 넓히는 `G_doc` 측정이 진행 중이다 |

또 하나의 결함은 검색 범위였다.

| 검색기 | 기존 범위 | 문제 |
|---|---|---|
| dense | 대상 문서 안 | 정상 |
| BM25 | 전체 문서 | 후보 32.6%가 대상 문서 밖 |

그래서 `bm25_doc`을 새로 만들었다. 이제 BM25도 dense와 똑같이 **대상 문서 안에서만** 후보를 찾는다.

## 5. 판정 기준

측정 전에 정한 기준이다.

| 조건 | 통과 기준 | 이유 |
|---|---|---|
| 유의성 | 95% CI 하한 > 0 | 다시 뽑아 재도 이기는지 확인 |
| 효과 크기 | MRR@10 +0.03 이상 | 바꿀 만큼 큰 개선만 승격 |
| 회귀 | 주요 유형에서 큰 하락 없음 | 평균만 오르고 특정 질문군이 망가지는 것 방지 |

CI가 0을 걸치면 **"졌을 수도 있다"**는 뜻이다.
점추정이 +0.0297처럼 좋아 보여도 CI 하한이 음수면 승격하지 않는다.

## 6. 측정 게이트

조용히 틀리는 실패가 많았기 때문에, 숫자보다 먼저 조건을 잠근다.

| 게이트 | 확인할 것 | 실패하면 |
|---|---|---|
| 인덱스 | `chroma_v2`, 30,002청크, 99문서 | 이전 수치와 비교 금지 |
| 청크 ID | 재인덱싱 뒤 `chunk_id` 집합 동일 | 정답지가 다른 청크를 가리킴 |
| 질문 파일 | 검색·리랭킹 모두 `qid_query_200.jsonl` | 후속 질문 29개가 서로 다른 문맥으로 평가됨 |
| 프리픽스 | e5만 `query:`/`passage:` 사용 | 에러 없이 성능만 떨어짐 |
| 정답지 | 캐시 `gold`가 v5 기준 | 풀링 편향 제거 전 값과 섞임 |
| 후보 순서 | dense 순서 뒤 BM25 전용 청크 | 동점일 때 입력 순서가 결과를 흔듦 |
